## Описание
Аутентифицированное сканирование уязвимостей целевого хоста (192.168.1.105, тот же LEMP-стенд) с помощью OpenVAS. Скан выполнен по SSH под пользователем `debian`.

Среда: собственная виртуальная лаборатория.

## Параметры скана
- Задача: `lemp scan`
- Начало: 2026-06-02 19:05:49 UTC, окончание: 19:13:35 UTC (~8 минут)
- Аутентификация: SSH, порт 22, пользователь `debian` — успешно
- Фильтрация: показаны результаты с минимальным Quality of Detection (QoD) 70%. Из 51 найденного результата после фильтрации осталось 8.

## Приоритизация и рекомендации по исправлению
1. **Critical (gnutls28, CVSS 9.8)** — закрывается установкой обновлённого пакета (`libgnutls30t64` ≥ 3.8.9-3+deb13u4). Исправлять первым: критическая уязвимость в TLS-библиотеке затрагивает все сервисы, использующие её для шифрования.
2. **High (bind9, CVSS 7.5)** — обновление пакетов `bind9-dnsutils`, `bind9-host`, `bind9-libs` до версии ≥ 1:9.20.23-1~deb13u1.
3. **Medium (krb5, CVSS 5.0)** — обновление пакетов Kerberos-библиотек.
4. **Medium (SSB, RFDS)** — аппаратные уязвимости процессора. В виртуальной среде зависят от хост-системы и микрокода; для полноценного устранения нужно обновление микрокода/BIOS на хосте, либо создание override, если хост не подвержен.
5. **Low:**
   - Отключить ICMP timestamp (защититься фаерволом, блокирующим ICMP Type 13/14) или отключить поддержку на хосте.
   - Отключить TCP timestamps: `net.ipv4.tcp_timestamps = 0` в `/etc/sysctl.conf`, применить через `sysctl -p`.
   - Убрать слабые MAC-алгоритмы SSH (`umac-64-etm@openssh.com`, `umac-64@openssh.com`) из конфигурации `sshd_config`.

## Взгляд защитника
- Главный вывод: **две находки высокого/критического уровня устраняются обычным обновлением пакетов** — это показывает, что регулярный патч-менеджмент закрыл бы большую часть риска без дополнительных действий.
- Низкоуровневые находки (ICMP/TCP timestamps, слабые MAC) — классический «information disclosure», используемый на этапе разведки атакующим (OS fingerprinting, расчёт uptime). По отдельности низкий риск, но в сумме снижают «отпечаток» системы перед атакующим.
- Рекомендация по процессу: включить регулярное (например, еженедельное) аутентифицированное сканирование и аналитику дельты между сканами, а не разовую проверку.
